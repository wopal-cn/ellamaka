## 会话级能力权限

### ELL-G1: 会话中可用的技能只看角色，不看这个会话实际需要什么（P0）

**Current**: 一个会话能用哪些技能，由它扮演的角色预先定好，全程不变。Wopal 即便判断某个会话需要额外某项技能，也无法让它在那个会话里出现——用户只能看到角色自带的那些。

**Target**: 会话的可用技能综合角色与该会话实际被赋予的能力共同决定：额外赋予的技能会出现在该会话的可用清单里，未赋予的技能在该会话不可见、也无法调用。

**Design**: `./DESIGN.md` 的 Ontology Loading Contract 与权限合并规则

**Exit**:
- [ ] 为某个会话赋予额外技能后，该技能出现在该会话的可用清单中
- [ ] 未赋予该会话的技能不可见，且无法被调用
- [ ] 会话的赋予结果能覆盖角色默认，而不是只做叠加
- [ ] 其他会话不受影响

### ELL-G2: 外部工具服务无法按会话授予（P1）

**Current**: 接入的外部工具服务只要连上就对所有会话可见，「这个会话只该用这几个服务」无法表达；用户也没有办法把某个服务限制在特定用途的会话里。

**Target**: 外部工具服务与其中的工具按会话授予：只有被赋予的服务与工具在该会话可见、可调用，其余不可见。

**Design**: `./DESIGN-ellamaka-tools.md`

**Exit**:
- [ ] 可按会话授予具体的外部服务
- [ ] 未授予的服务及其工具在该会话不可见
- [ ] 未授予的工具即便被要求调用也不会执行

## DSH 插件包

### ELL-G3: Wopal 的角色与能力还是散装配置，装不了（P0）

**Current**: Wopal 的角色设定与配套能力以几个分散的配置目录存在，用户要自己把这些文件放到正确位置才能用。没有可安装、可升级的分发形态，也无法确认版本之间是否兼容。

**Target**: 发布为一个标准插件包，用户执行一条安装命令即可获得三个角色配置单。后续升级包本身即可，用户对配置单的个性化修改不会被覆盖。

**Design**: `./DESIGN-dsh-web.md` 的 wopal 插件包

**Exit**:
- [ ] 一条安装命令即可完成安装与注册
- [ ] 安装后三个角色配置单出现在配置单列表中
- [ ] 升级插件包不会覆盖用户对配置单的个性化修改
- [ ] 包的形态符合设计中的包结构定义

### ELL-G4: 无法收窄某个角色可用的工具（P0）

**Current**: 一个角色的工具范围由角色本身定死。用户能做的事是"换一个角色"，而不能在保留角色设定的前提下，只给它更少的工具——想配一个更专注、更受限的助理是做不到的。

**Target**: 配置单在挂载时声明自己允许哪些工具，不在允许范围内的工具对该角色完全不可见——不只是被拒绝调用，而是根本不出现。收窄只影响使用该配置单的角色，不影响其他角色。

**Design**: `./DESIGN-dsh-web.md` 的武器架能力

**Exit**:
- [ ] 通过配置单可以只给某个角色一部分工具
- [ ] 未允许的工具在该角色视野中不出现，也不可调用
- [ ] 其他角色不受该配置单影响

### ELL-G5: 界面无法按空间定制（P0）

**Current**: 无论打开哪个空间，界面看起来完全一样。空间无法拥有自己的品牌标识、色板或对界面细节的取舍，用户也无法一眼从界面判断当前在哪个空间。

**Target**: 界面按空间定制：进入某个空间的会话时，界面自动应用该空间定义的主题与品牌资源；可定制的范围为品牌位、输入区信息条、会话头部动作位与自定义工具卡片等既定位置，不整块替换界面。未定义皮肤的空间保持默认外观。

**Design**: `./DESIGN-dsh-web.md` 的空间皮肤插件

**Exit**:
- [ ] 进入不同空间的会话时，界面呈现该空间的主题与品牌
- [ ] 未定义皮肤的空间保持默认外观，不报错
- [ ] 定制限定在既定位置，界面整体结构不变
- [ ] 主题变量与现有设计语言一致

### ELL-G6: 实验性配置无法与主环境隔离运行（P0）

**Current**: 只有一套运行环境，试用第三方配置就必须在主环境里动，出了问题会直接影响正在使用的工作台；也没有办法让两个配置版本同时跑起来做对比。

**Target**: 实验性配置以独立进程运行，拥有自己的数据目录，不进入主环境、不共享配置存放位置。用户可在工作台中把它注册为一个独立入口，看到它的地址与健康状态；主环境继续运行当前配置不受影响，两个版本可同时在线。

**Design**: `./DESIGN-dsh-web.md` 的多 profile 解耦

**Exit**:
- [ ] 可以单独启动一个实验性配置，且它使用独立的数据目录
- [ ] 实验进程的运行不影响主环境
- [ ] 工作台能展示实验入口的地址与健康状态
- [ ] 历史配置与当前配置可以同时运行

## Config Consumption

### ELL-G11: 引擎没有空间级配置消费面，面板写入无落点（P0）

**Current**: 引擎能读三层配置文件，但 `Config.Service` 只有 `get`/`getGlobal`/`update`（写死项目目录 `config.json`）/`updateGlobal`，没有空间级读写与来源标注；`wopal-space` 路由组没有配置端点，Workbench 面板查不到继承状态、也没有写入入口；`DialogSettings` 是本地偏好 dialog，无作用域切换。

**Target**: 按 `./DESIGN-config-engine.md` 实现：`GET /wopal-space/config` 由引擎加载状态直答（生效树 + 每项来源）；`PATCH /wopal-space/config` 与 `reset-key` 经 CLI adapter 转发 `config.operation`（引擎无写入代码，空间 `settings.jsonc` 写请求返回只读错误码）；面板作用域切换 + 继承状态标签（覆盖 `wopal.pluginConfig` 插件配置）；配置写入后 `ellamaka` 段经文件监听热重载即时生效。

**Design**: `./DESIGN-config-engine.md`；`../../../docs/products/wopal-space/DESIGN-config-settings.md`（总体分层与唯一写入者）

**Exit**:
- [ ] `GET /wopal-space/config` 返回生效配置树与每项来源（全局/空间公共/空间本地），与引擎合并链同源
- [ ] `PATCH /wopal-space/config` 经 adapter 落到 CLI，写目标为 `settings.local.jsonc`；目标为空间 `settings.jsonc` 时返回只读错误码
- [ ] `reset-key` 删除本地层键后配置回落继承源
- [ ] 面板作用域切换可用，继承态/覆写态/悬停诊断按数据渲染，含插件配置项
- [ ] CLI 写入 `ellamaka` 段后当前实例热重载生效，无需重启

## Workbench 交互

### ELL-G7: 同一个会话能在多个面板里被重复打开（P0）

**Current**: 从会话列表打开一个会话时，工作台不检查它是否已经开着。用户可能同时看到同一个会话的两份视图，在其中一处输入的内容在另一处不出现，容易误判消息有没有发出，也分不清哪个才是在用的窗口。

**Target**: 打开一个已开启的会话时，不新建第二个视图，而是直接切换到它所在的空间与页签，并高亮闪烁对应面板，让用户立刻定位到它。未开启的会话仍按现有规则分配位置。

**Design**: `./DESIGN-workbench.md` 的跨空间智能 Tab/Panel 分发与定位

**Exit**:
- [ ] 重复打开已开启的会话不会产生第二份视图
- [ ] 视图自动切换到该会话所在的空间与页签
- [ ] 目标面板有可见的高亮提示帮助定位
- [ ] 未开启会话的打开行为保持不变

### ELL-G8: 一轮对话结束时看不到改了哪些文件（P0）

**Current**: 一轮对话里若改动了多个文件，改动散落在各次编辑记录中，用户要逐条翻看才能知道这一轮总共动了什么、改了多少，也无法从整体上决定要不要复核。

**Target**: 每轮对话末尾给出这一轮的改动汇总：修改的文件数、增删行数，以及直接进入复核的入口。它回答"这一轮的结果是什么"，与过程中的单次编辑记录形成对照。

**Design**: `./DESIGN-workbench.md` 的 Chat 视图

**Exit**:
- [ ] 每轮对话末尾显示该轮的改动汇总
- [ ] 汇总显示修改文件数与增删行数
- [ ] 可从汇总直接进入复核
- [ ] 没有改动的轮次不显示汇总

## 分发流水线

### ELL-G9: 发布时没有校验产物身份是否一致（P1）

**Current**: 产物中内嵌的身份信息与本次发布所应具有的身份是否吻合，发布流程不做检查。一旦不一致，错误的产物会被正常发布出去，问题要到用户安装后才暴露。

**Target**: 发布流程在产物构建后校验命令行工具、桌面端与清单三处的身份信息完全一致，任何一处不符即中断发布，不让不一致的产物离开流水线。

**Design**: `./DESIGN-distribution.md` 的 Canonical Manifest 与 Runtime Identity Surfaces

**Exit**:
- [ ] 命令行工具发布时校验其内嵌身份与本次发布一致
- [ ] 桌面端发布时校验其内嵌身份与本次发布一致
- [ ] 任一校验不通过时发布中断

## Desktop 与 onboarding

### ELL-G10: 桌面端引导流程还按旧的类型列表工作（P0）

**Current**: 桌面端引导流程向命令行工具询问"有哪些类型可选"，期望得到一份固定的分支列表，并为其预留了很长的等待时间。安装方式改变后，这份列表的来源与形态都变了，桌面端仍按旧预期解析，引导流程会拿到错误或空的结果。

**Target**: 引导流程按新的返回内容工作，能正确展示可选类型与完成初始化。等待时间按实际耗时重新确定，相关测试也改为覆盖新形态。

**Design**: `./DESIGN-onboarding.md`

**Exit**:
- [ ] 引导流程正确展示新版返回的可选类型
- [ ] 用新形态完成一次完整初始化
- [ ] 等待时间按实际耗时重新评估，不再沿用旧值
- [ ] 相关测试覆盖新形态而非旧的分支列表
